# 회로 계열 확대 실험 결과

새로운 게이트 또는 미분 각도 절감 사례는 이번 고정 범위에서 발견되지 않았다. 추가 비활성 기호는 기존 ChebyshevRx의 두 크기와 두 readout에 해당하는 네 슬롯에만 나타났다. 각 슬롯에서 기호 두 개를 추가로 제거하지만 최종 융합 게이트 수와 학습 가능한 angle 작업 수는 그대로다.

## 실행과 분모

로컬 macOS에서 고정된 외부 소스와 Qiskit 1.2.4, NumPy 1.24.4로 실제 실행했다. 서버 full 실험의 Linux timing과 섞어 집계하지 않았다. 120개 명목 슬롯 중 layer 인자 중복 18개를 표시하고 102개를 실행했다. 대상은 10개 기본 생성 모듈이며 기존 미구성 3개 모듈의 제외 사유를 유지했다. 기본 random constructor seed는 0이다.

| 최종 상태 | 슬롯 수 | 해석 |
|---|---:|---|
| 학습 가능한 회로, alignment 검증 가능 | 82 | 커널·미분 및 두 update 검증 |
| 학습 파라미터 없음 | 18 | 커널·빈 미분 등 적용 가능한 검사 |
| 학습 파라미터 있음, alignment 미정의 | 2 | 커널·kernel derivative·고정 파라미터 예측만 검사 |
| constructor의 층 인자 중복 | 18 | 실행하지 않고 중복 대상 명시 |

따라서 102개를 모두 성공적인 학습 실험이라고 쓰면 안 된다. 또한 10모듈을 독립 회로 계열 10개로 자동 계산하지 않는다.

## 추가한 비교 구현

새 readout에 맞춘 elementary common-isometry suffix 기준선과 gate-angle 공유 미분기를 추가했다. 기준선은 local XYZ에만 맞춘 말단 규칙을 전체 Pauli readout에 그대로 적용하지 않는다. 입력 독립 등거리 suffix와 support-confined 분리 조건을 검사한 뒤 기존 boundary 운반 및 같은 축 융합을 수행한다. 이는 충분조건이며 모든 기호적 최적화를 포괄하지 않는다.

공유-angle 미분기는 RBF가 아니라 측정 특징에 parameter-shift를 적용한다. 기호들이 같은 각도를 공유하면 미분 특징을 재사용하고, 하나의 기호가 여러 게이트에 나오면 chain-rule 기여를 모두 더한다. 기존 배포판의 구현은 덮어쓰지 않았다.

6개 단위 테스트가 통과했다. 테스트에는 얽힘으로 generator support가 확장되어 처음에는 겹치지 않던 데이터 게이트와 만나게 되는 반례를 포함한다.

## 수치 검증

각 슬롯을 probe seed 812와 1907, seed당 5입력에서 검사했다. 총 1,626개의 파라미터 좌표에 대해 유한차분을 계산했다. 원본 Qiskit 특징은 base point에서 비교했고, 유한차분은 compiled IR에서 수행했다. 새 shot 실험이나 독립 연구자 검토는 아니다.

| 항목 | 최대 절대 차이 |
|---|---:|
| Qiskit source 특징 대 compiler IR | 3.89e-15 |
| Shared-angle 특징 Jacobian 대 analytic | 1.78e-15 |
| Kernel Jacobian 대 유한차분 | 7.00e-10 |
| 커널 보존 | 3.55e-15 |
| Objective gradient 대 유한차분 | 9.38e-9 |
| 두 update 파라미터 경로 보존 | 4.44e-16 |
| Ridge 예측 보존 | 1.67e-15 |

모두 각 검사에 정한 허용값 이내다. 실행 결과를 다시 읽어 308개 manifest 파일과 3,252개 저장 배열의 해시·유한성·양 군 보존을 재검사했다. 이 재검사는 새로운 전체 시뮬레이터 재실행이 아니다.

## 영효과와 수정 내역

최종 융합 연산 또는 trainable angle 작업이 감소한 슬롯은 **0/102**다. 이는 이 기본 constructor·readout·지원 규칙 범위의 결과일 뿐, 다른 회로에서 절감이 불가능하다는 증명이나 문헌 prevalence 추정이 아니다.

추가 기호가 있는 네 슬롯은 ChebyshevRx, 2층, n=2/4, local XYZ/Pauli weight≤2 조합이다. 두 readout에서 같은 소스 기호를 다시 센 것이므로 네 개의 독립 발견이나 여덟 개의 새로운 소스 기호가 아니다. Local Z에서는 해당 추가 인증이 없다.

첫 실행에서 ParamZFeatureMap local Z 두 설정의 centered alignment가 정의되지 않아 예외가 났다. 실패 run을 지우지 않고 AMENDMENT_KO.md에 처리 변경을 공개했다. 수정 실행은 이 두 설정의 학습을 생략하고 커널·미분 검증만 수행한다. 커널 오류를 무시하거나 임계값을 완화한 것이 아니다.

최종 run은 `results/survey_20261001T085953_343158Z`다. 첫 진단 run `survey_20261001T085847_231988Z`도 보존했다. 첫 run의 코드 해시는 기록되어 있지만, 실행 소스 패키지는 명시적 alignment 처리를 추가한 최종 버전이다. 서버에서 제공 코드를 실행하면 최종 버전의 새로운 run을 생성한다.

## 원고와 다음 판단

PRX v4에는 full timing의 반복 이득과 이번 영효과를 모두 반영했다. 가능한 주장은 readout별 정확한 인증과 구현별 계산 효과의 구분이다. 여러 독립 회로 계열에서 shared-angle/QPU 비용을 줄이는 방법이라는 주장은 아직 뒷받침되지 않는다.

이번 조사로 정한 진입 조건을 만족하는 새 자원 절감 후보가 없으므로 후속 대규모 timing은 시작하지 않았다. 다음 연구 확장은 지원 운반 규칙 또는 대상 회로군을 넓히는 별도 설계가 필요하며, 기존 수치를 더 반복하는 것으로 이 빈칸이 해결되지는 않는다. 새 설계를 채택한다면 그 분모와 선택 과정을 다시 명시해야 한다.
